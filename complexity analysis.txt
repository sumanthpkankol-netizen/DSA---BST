COMPLEXITY ANALYSIS
===================

1. BST SEARCH

Best Case:
O(1)

The searched element is the root of the tree.

Average Case:
O(log n)

This occurs when the BST is reasonably balanced.

Worst Case:
O(n)

This occurs when the BST becomes highly skewed.


2. BST INSERTION

Best Case:
O(1)

Average Case:
O(log n)

Worst Case:
O(n)


3. LINEAR SEARCH

Best Case:
O(1)

The required element is the first element.

Average Case:
O(n)

The algorithm may need to check approximately half of the elements.

Worst Case:
O(n)

The required element is at the end or is not present.


4. TREE TRAVERSAL

Inorder traversal:
O(n)

Every node must be visited once.


5. SPACE COMPLEXITY

BST:
O(n)

Each identification number requires one tree node.

Linear Search:
O(n)

The array stores all identification numbers.


6. EFFECT OF KEY LENGTH

The BST height is mainly affected by the number of keys
and their insertion order.

However, longer identification numbers can increase the
time required to compare two strings.

If L represents the average key length:

Balanced BST search:
O(L log n)

Worst-case BST search:
O(Ln)

Linear search:
O(Ln)


7. EFFECT OF INSERTION ORDER

Insertion order has a major effect on BST height.

A balanced insertion order can produce a shorter tree.

Sorted or reverse-sorted insertion can produce a highly
skewed tree.

For n = 8:

Best height ≈ 3 edges
Worst height = 7 edges
Given tree height = 5 edges


8. SUITABLE APPROACH FOR A GROWING DATABASE

An ordinary BST may become unbalanced as the database grows.

A self-balancing BST such as an AVL Tree or Red-Black Tree
is more suitable because it maintains approximately O(log n)
search and insertion performance.

For large database systems, B-Tree or B+ Tree based indexing
can also be used.
